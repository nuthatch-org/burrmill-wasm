Burrmill and DuckDB-Wasm, side by side

Each authored view of the nest, run in this tab by both engines over the same segments on the public mirror. Cold is a fresh engine with nothing kept: every request carries a query string unique to the run, so the browser's HTTP cache cannot answer it. Burrmill fetches each segment whole and checks it against the SHA-256 its key names; DuckDB-Wasm is handed the same URLs and makes its own range requests, and checks nothing. Warm is the same statement again on the same engine. Burrmill's time includes encoding the rows to JSON lines; DuckDB's stops when it hands over Arrow, and its rows are encoded afterwards, untimed, so the comparison leans DuckDB's way. Both answers are compared as multisets of rows.
